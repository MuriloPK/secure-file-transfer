# PROMPT — CRIAR APLICAÇÃO COMPLETA DE TRANSFERÊNCIA SEGURA DE ARQUIVOS

Quero que você crie do zero uma aplicação completa, funcional e pronta para execução local, seguindo rigorosamente todos os requisitos abaixo.

Não quero apenas exemplos, pseudocódigo ou trechos isolados. Quero o projeto completo, compilável, testável e executável.

A aplicação será utilizada em dois computadores diferentes e terá como finalidade transportar arquivos ZIP de até 200 MB utilizando um armazenamento intermediário autorizado.

O conceito será semelhante a PUSH/PULL:

PC A:
Seleciona arquivo → prepara → criptografa → divide → publica

PC B:
Lista transferências → baixa partes → valida → remonta → descriptografa → entrega ZIP original

IMPORTANTE:

implementar mecanismos para ocultar atividade, burlar DLP, firewall, proxy, auditoria, antivírus, EDR, políticas corporativas ou controles de segurança.

criar logs falsos ou mascarar operações.

# 2. OBJETIVO PRINCIPAL

Criar uma aplicação chamada:

secure-file-transfer

Ela deve permitir:

1. Selecionar um arquivo ZIP.
2. Validar tamanho máximo.
3. Calcular SHA-256 do arquivo original.
4. Dividir o arquivo em chunks.
5. Criptografar os chunks.
6. Calcular SHA-256 individual de cada chunk criptografado.
7. Criar um manifest.json.
8. Publicar tudo no armazenamento.
9. Outro computador listar as transferências disponíveis.
10. Selecionar uma transferência.
11. Baixar os chunks.
12. Validar cada chunk.
13. Identificar automaticamente chunks ausentes ou corrompidos.
14. Baixar novamente somente os chunks inválidos.
15. Descriptografar.
16. Remontar o arquivo.
17. Calcular SHA-256 final.
18. Comparar com SHA-256 original.
19. Somente disponibilizar o arquivo quando a integridade estiver 100% validada.

# 6. CRIPTOGRAFIA

Utilizar:

AES-256-GCM

Cada chunk deverá ser criptografado individualmente.

Cada chunk precisa possuir nonce/IV exclusivo.

Nunca reutilizar nonce com a mesma chave.

Utilizar APIs seguras disponíveis no Java/JCA.

Não implementar algoritmo criptográfico manualmente.

Cada chunk deverá possuir:

* número
* tamanho original
* tamanho criptografado
* SHA-256 criptografado
* nonce/IV necessário
* nome interno

A senha/chave NÃO deverá ser salva diretamente no repositório.

Desenvolver uma estratégia de chave configurável.

Para ambiente local/dev poderá utilizar variável de ambiente:

TRANSFER_SECRET

Nunca colocar chave hardcoded no código.

Nunca versionar segredo.

Adicionar:

.env.example

apenas como exemplo.

# 10. UPLOAD / PUSH

Fluxo:

arquivo.zip

→ valida extensão

→ valida tamanho

→ gera transferId

→ calcula SHA-256 original

→ lê utilizando streaming

→ divide em chunks

→ criptografa cada chunk

→ calcula SHA-256 do chunk criptografado

→ grava chunk temporário

→ monta manifest

→ publica chunks

→ publica manifest por último

O manifest deverá ser publicado por último.

Isso é importante porque a existência do manifest indicará que a transferência terminou corretamente.

Se falhar antes:

não apresentar aquela transferência como disponível.

---

# 11. DOWNLOAD / PULL

Fluxo:

listar transfers

→ selecionar transferId

→ baixar manifest

→ validar manifest

→ verificar espaço disponível

→ baixar chunks

→ validar SHA-256 individual

→ baixar novamente chunks inválidos

→ descriptografar chunks

→ remontar arquivo temporário

→ calcular SHA-256 original

→ comparar hash

→ somente depois mover para destino final

Nunca sobrescrever diretamente o destino enquanto o download estiver incompleto.

Utilizar arquivo temporário.

Exemplo:

arquivo.zip.download

Ao concluir:

arquivo.zip.download

→ valida

→ move atomicamente, se possível

→ arquivo.zip
